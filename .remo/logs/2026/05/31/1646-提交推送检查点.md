## 摘要

ReMo 将每次 commit 和 push 定义为强制 checkpoint：必须生成或更新日志，并同步受影响的知识库内容。

## 背景

commit 和 push 是项目状态对内固化、对外发布的关键节点。如果这些节点没有同步更新 ReMo，未来 Agent 可能需要重新扫描 diff、commit 历史和代码库来理解已发布变化。

## 关键信息

- 提交前必须检查 staged diff，并更新对应 ReMo 日志。
- 提交前必须更新受影响的 `.remo/knowledge/` 文件和必要的 `.remo/knowledge/index.md`。
- 描述本次工作的 ReMo 更新应进入同一个 commit。
- 推送后应在日志中补充 commit hash、分支、remote 和推送结果。
- 如果没有新的稳定知识，也要在日志中说明原因，而不是编造低信号知识。

## 决策或结果

commit/push 成为 ReMo 的强制记忆维护时机，用来保证 Git 历史、日志和知识库保持同步。
