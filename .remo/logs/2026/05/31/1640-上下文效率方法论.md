# 2026-05-31 16:40 上下文效率方法论

## 类型

决策

## 摘要

ReMo 正式引入 Context-Efficient Project Memory 方法论，用 Context ROI 和 SKR 控制日志与知识库的详略尺度。

## 背景

ReMo 的目标不是尽可能多地记录，而是让 LLM 在未来功能开发时用最少上下文理解项目。日志如果太细会变成流水账，知识库如果太满会增加阅读成本；但如果太粗，又会导致 Agent 重新扫描代码库和重复推理。

## 关键信息

- ReMo 采用三条原则：Route before read、Distill before store、Evidence before trust。
- Context ROI 判断一条记忆是否值得写入：它节省的未来上下文成本是否大于自身阅读成本。
- SKR 是 Signal Knowledge Ratio，要求每句话都帮助未来 Agent 理解、决策或避免重复发现。
- 高价值记忆包括架构边界、跨文件业务规则、稳定领域概念、重要决策、常见坑和必须遵守的约定。
- 低价值记忆包括文件列表式描述、显而易见的代码事实、临时调试噪声、完整聊天摘要和无结论输出。

## 决策或结果

ReMo 的日志和知识库写入不再只看“是否发生了事情”，而是先判断这条记忆是否能提升未来 LLM 的上下文效率。
